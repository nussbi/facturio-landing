Types d’adresse de la QR-facture : structurée ou combinée (type S ou type K)

7 septembre 2026 · facturio.ch

Les QR-factures encodent les adresses de deux manières : structurée (type S) et combinée (type K). Depuis fin 2025, seules les adresses structurées sont acceptées de manière fiable.

Structurée (type S)

L’adresse est répartie en champs distincts : nom, rue, numéro, code postal, ville et pays. C’est le format que la norme exige désormais dans le code QR.

La séparation des champs permet à une application de paiement de valider chaque partie par rapport aux données postales, ce qui explique pourquoi les adresses structurées se lisent et se traitent de manière fiable.

Dans la charge utile QR, chaque élément est délimité sur sa propre ligne, de sorte que le système récepteur sait exactement quelle partie est la rue et laquelle est la ville.

C’est le format que vos fiches clients devraient stocker, afin que chaque QR-facture que vous générez porte des adresses structurées sans effort supplémentaire.

  • Nom, rue, numéro, code postal, ville, pays — chacun dans son propre champ.

Combinée (type K)

L’adresse tient dans moins de lignes de texte libre, comme « Musterstrasse 12, 8000 Zürich » dans un seul champ. Pratique pour l’impression, mais elle n’est plus acceptée dans les données lisibles par machine.

Le format combiné était une commodité héritée qui fusionnait l’adresse en une ou deux lignes non structurées.

Depuis fin 2025, les adresses combinées ne sont plus valides dans les données de la QR-facture. Une QR-facture construite sur une adresse combinée n’est pas conforme à la norme et peut ne pas se lire.

Le changement s’applique aux données du code QR. L’adresse imprimée sur la facture elle-même peut toujours être formatée comme vous le souhaitez, tant que les données encodées sont structurées.

Pourquoi c’est important

Une QR-facture peut paraître parfaitement correcte alors que ses données d’adresse sous-jacentes sont combinées, puis échouer à la lecture. L’apparence visuelle ne vous dit rien sur le format des données.

Lorsqu’une adresse est combinée, la banque réceptrice ne peut pas l’analyser de manière fiable, raison pour laquelle la norme la rejette désormais purement et simplement.

L’échec ne se manifeste qu’au moment du paiement, lorsque l’application du client refuse le code ou lit mal l’adresse. À ce stade, la facture a déjà été envoyée.

Pour les entreprises qui conservent encore les adresses sous forme de lignes de texte libre, la solution consiste à migrer les données, et non à rafistoler des factures individuelles.

Migrer vers des adresses structurées

Décomposez chaque adresse en champs structurés dans vos fiches clients : nom, rue, numéro, code postal, ville et pays. Faites-le une fois par client, puis laissez le logiciel générer des données conformes.

Veillez à traiter le numéro comme un champ à part entière. La norme suisse le veut séparé du nom de la rue, et les fusionner dans un seul champ est une source fréquente d’échec.

Pour les adresses étrangères, maintenez le champ pays correct, car le format structuré inclut le pays comme élément distinct.

Après la migration, régénérez et testez la lecture d’une QR-facture pour confirmer que les données structurées sont émises correctement avant de vous y fier pour l’ensemble de votre clientèle.

  • L’adresse structurée (type S) est désormais requise dans les données QR.
  • L’adresse combinée (type K) n’est plus acceptée dans le code QR.
  • Stockez nom, rue, numéro, code postal, ville et pays séparément.
  • L’adresse imprimée peut toujours être formatée librement.
